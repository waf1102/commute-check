## Functional Requirements

### 1. User Management & Configuration
- [x] **[USER-LOC] Location Settings:** User must be able to set their location (lat/long) for weather data.
- [x] **[USER-SCHED] Notification Schedule:** User must be able to set a specific daily time (e.g., 07:00 AM) for the Go/No-Go assessment.
- [x] **[USER-THRES] Personal Thresholds:**
    - Minimum Temperature: Default 40°F (Caution), 32°F (No-Go).
    - Maximum Wind Speed: Default 20 mph (Caution), 35 mph (No-Go).
    - Rain Tolerance: Default "Any rain" (No-Go), but configurable (e.g., light rain is OK).
- [x] **[USER-WEBHOOK] Webhook Management:** Input field for Discord/generic webhook URL.

### 2. Assessment Engine
- [x] **[ENG-DATA] Data Source:** Fetch hourly weather data from Open-Meteo API.
- [x] **[ENG-ALGO] Penalty Algorithm:**
    - Calculate "Apparent Temperature" (Wind Chill).
    - Deduction-based scoring: 100 points start.
    - **Red Flag Factors (Immediate No-Go):**
        - Temperature < user_min_temp.
        - Wind Speed > user_max_wind.
        - Precipitation Probability > user_rain_threshold.
        - Weather Code (WMO) indicating snow, ice, or thunderstorms.
- [x] **[ENG-OUT] Output:** A clear status (Go, Caution, No-Go) with a brief justification (e.g., "Go - Clear skies, 55°F, light wind").

### 3. Notification System
- [x] **[NOTIF-TRIG] Trigger:** Scheduled task runs at the user's configured time.
- [x] **[NOTIF-PAY] Payload:** Send a formatted message to the user's webhook.
- [x] **[NOTIF-CONT] Content:** Status icon (🟢, 🟡, 🔴), current weather summary, and the "riding recommendation."

### 4. Web Dashboard (UI)
- [x] **[UI-STATUS] Status Overview:** Display current weather and today's recommendation.
- [x] **[UI-FORM] Settings Form:** Simple, mobile-friendly form to update thresholds and webhook.
- [x] **[UI-HIST] History (Optional for MVP):** Log of previous days' recommendations (Basic dashboard status).

## Non-Functional Requirements
- [x] **[NFR-PERF] Performance:** Assessment and notification should complete within < 5 seconds.
- [x] **[NFR-RELI] Reliability:** The scheduler must be resilient to backend restarts (use a persistent job store if needed).
- [x] **[NFR-SEC] Security:** Webhooks and user coordinates should be stored securely in the database.
- [x] **[NFR-PORT] Portability:** Containerized with Docker for easy self-hosting.

## Tech Stack Requirements
- [x] **[TECH-BACK] Backend:** FastAPI (Python 3.11+)
- [x] **[TECH-FRONT] Frontend:** SvelteKit (TypeScript preferred)
- [x] **[TECH-DB] Database:** SQLite (via SQLAlchemy or SQLModel)
- [x] **[TECH-STYLE] Styling:** Vanilla CSS (or a lightweight CSS framework if needed)
- [x] **[TECH-API] Weather API:** Open-Meteo (No API key required)
