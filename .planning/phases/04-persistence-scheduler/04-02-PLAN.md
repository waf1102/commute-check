<objective>
This plan refactors the main API to be database-driven and introduces the background scheduler. It creates a CRUD layer for database interactions and wires it into the API endpoints. It also sets up the APScheduler to run the commute assessment automatically.

**Purpose:** To make the application stateful and automated, allowing user settings to be saved and checks to run without manual intervention.
**Output:** A revised API, a new CRUD service, and an integrated scheduler.
</objective>

<task type="auto">
  <name>Task 2: Implement the Scheduler</name>
  <files>
    - app/scheduler.py
  </files>
  <action>
    Create `app/scheduler.py` to define and manage the `APScheduler`.
    - Import `AsyncIOScheduler` from `apscheduler.schedulers.asyncio`.
    - Import `SQLiteJobStore` from `apscheduler.jobstores.sqlalchemy`.
    - Configure job stores for persistence: `{'default': SQLiteJobStore(url='sqlite:///jobs.db')}`.
    - Create the `scheduler = AsyncIOScheduler(jobstores=jobstores)`.
    - Define an async function `run_assessment_job()`. This function will:
        1. Create a database session.
        2. Call `crud.get_user_config` to get the user's settings (assume user_id=1).
        3. If a config exists, call the `AssessmentEngine` and `WeatherClient` similar to the existing `/assess` endpoint.
        4. If a webhook URL is present, trigger the notification.
    - The `start_scheduler` function should add the `run_assessment_job` to the scheduler, set to run every 1 minute for testing purposes (`trigger='interval', minutes=1`).
    - The `shutdown_scheduler` function should shut down the scheduler.
  </action>
  <verify>
    <automated>python -c "from app.scheduler import scheduler; assert scheduler is not None"</automated>
  </verify>
  <done>
    `app/scheduler.py` is created with scheduler configuration, a job definition, and start/shutdown functions.
  </done>
</task>

<task type="auto">
  <name>Task 3: Refactor Main API and Integrate Scheduler</name>
  <files>
    - app/main.py
  </files>
  <action>
    Refactor `app/main.py` to use the database and run the scheduler.
    1.  **Add Lifespan Manager:**
        - Import `contextlib.asynccontextmanager`.
        - Import `create_db_and_tables` from `database`.
        - Import `start_scheduler`, `shutdown_scheduler` from `scheduler`.
        - Create a `lifespan` async context manager. On startup (`yield`), it should call `create_db_and_tables()` and `start_scheduler()`. On shutdown, it should call `shutdown_scheduler()`.
        - Add `lifespan=lifespan` to the `FastAPI()` constructor.

    2.  **Refactor Endpoints:**
        - Create an `APIRouter`. Define new endpoints on the router.
        - Create a `GET /config` endpoint that uses `crud.get_user_config` to return the current settings.
        - Create a `POST /config` endpoint that takes a `UserConfig` model and uses `crud.create_or_update_user_config` to save it.
        - **Remove the old `/assess` endpoint.** Its functionality is now handled by the scheduler and can be triggered by updating config.
        - Include the router in the main app.
  </action>
  <verify>
    <automated>grep -q "lifespan=lifespan" app/main.py && grep -q "POST /config" app/main.py</automated>
  </verify>
  <done>
    `app/main.py` is updated with a scheduler lifespan manager and new CRUD-based API endpoints for managing configuration. The old, stateless `/assess` endpoint is removed.
  </done>
