    1.  **Setup a Test Database:**
        - Use an in-memory SQLite database for testing to ensure test isolation.
        - Create a pytest fixture that sets up a test database engine and session, and overrides the `get_session` dependency in the FastAPI app. This is a standard pattern for testing FastAPI applications with databases.

    2.  **Write New Tests:**
        - Remove the existing `test_assess_commute` function.
        - Write `test_read_config` to test the `GET /config` endpoint. It should handle the case where no config exists and the case where it does.
        - Write `test_create_config` to test the `POST /config` endpoint.
        - Write `test_update_config` to test that posting to `/config` a second time updates the existing entry.
  </action>

<task type="checkpoint:human-verify" gate="blocking">
  <name>Task 2: Manual End-to-End Verification</name>
  <what-built>
    The entire persistence and scheduler system. This includes:
    - A database for storing user settings (`commute_check.db`).
    - A persistent job store for the scheduler (`jobs.db`).
    - New API endpoints (`GET /config` and `POST /config`).
    - A background scheduler that automatically runs the assessment logic.
  </what-built>
  <how-to-verify>
    1.  **Start the application:** Run `uvicorn app.main:app --reload` in your terminal.
    2.  **Check for new files:** Verify that `commute_check.db` and `jobs.db` have been created in the root directory.
    3.  **Configure the user settings:** Use `curl` or an API client to send a POST request to `http://127.0.0.1:8000/config`. Use a real (but non-critical) webhook URL and your location.
        ```bash
        curl -X POST -H "Content-Type: application/json" -d '{
          "name": "My Commute",
          "lat": 47.6062,
          "lon": -122.3321,
          "webhook_url": "YOUR_DISCORD_WEBHOOK_URL",
          "schedule_time": "07:00",
          "min_temp_caution": 45,
          "min_temp_no_go": 38,
          "max_wind_caution": 15,
          "max_wind_no_go": 25,
          "rain_threshold": 30
        }' http://127.0.0.1:8000/config
        ```
    4.  **Verify the configuration:** Send a `GET` request to `http://127.0.0.1:8000/config` and confirm the settings you just posted are returned.
    5.  **Monitor the logs:** Watch the terminal where the app is running. Within one minute, you should see logs from the scheduler as it runs the assessment job.
    6.  **Check for notification:** You should receive a Discord notification at your webhook URL with the commute assessment.
    7.  **Restart and verify persistence:** Stop the `uvicorn` server (Ctrl+C) and restart it. The application should start up, and the scheduler should continue to run the job with the saved settings, sending another notification within a minute.
  </how-to-verify>
  <resume-signal>
    Type "approved" if all steps worked as expected. If not, describe the issue.
  </resume-signal>
</task>
