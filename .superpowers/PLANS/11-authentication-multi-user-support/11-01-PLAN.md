    - `create_access_token` should generate a JWT string.
    - The `/register` endpoint should create a new user with a hashed password.
    - The `/login` endpoint should return a JWT for a valid user and password.
    - The `/login` endpoint should return a 401 for an invalid password.

        - `get_password_hash(password: str) -> str` using `bcrypt`.

        - `create_access_token(data: dict, expires_delta: timedelta | None = None) -> str` using `jose.jwt`. It should use a secret key and algorithm (HS256) loaded from environment variables (`SECRET_KEY`, `ALGORITHM`).

<threat_model>
## Trust Boundaries
| Boundary | Description |
|---|---|
| Client -> API | Untrusted user input for registration and login. |
| API -> Database | Storage of user credentials. |

## STRIDE Threat Register
| Threat ID | Category | Component | Disposition | Mitigation Plan |
|---|---|---|---|---|
| T-11-01 | Tampering | User Password | Mitigate | Passwords will be hashed using bcrypt via `get_password_hash` before being stored in the `User` model. Plaintext passwords are never stored. |
| T-11-02 | Information Disclosure | JWT Secret Key | Mitigate | The `SECRET_KEY` used for signing JWTs will be loaded from an environment variable and not hardcoded in the source. |
| T-11-03 | Spoofing | User Identity | Mitigate | Login endpoint (`/api/login`) will verify credentials using `verify_password` before issuing a token, preventing users from spoofing others without their password. |
</threat_model>
