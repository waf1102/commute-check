  <name>Task 1: Update API Client to Send JWT</name>
  <files>
    - frontend/src/lib/api.ts
    - frontend/src/lib/auth.ts
  </files>
  <action>
    1.  Create a file `frontend/src/lib/api.ts` if it doesn't exist, or modify the existing API call logic.
    2.  This file will encapsulate `fetch` calls to the backend.
    3.  Modify the functions that call protected endpoints (like `GET /config`). These functions should:
        a. Import the `jwt_token` store from `auth.ts`.
        b. Use `get(jwt_token)` to retrieve the current token value.
        c. If a token exists, add it to the `Authorization` header of the `fetch` request: `Bearer <token>`.
        d. If no token exists, the request should not be sent, or it should be expected to fail.
    4.  Refactor existing pages (like `+page.svelte`) to use this new `api.ts` service instead of direct `fetch` calls.
  </action>
  <verify>

    </automated>
  </verify>
  <done>
    All relevant frontend API calls to the backend are now sending the JWT for authentication.
  </done>

<task type="auto" tdd="false">
  <name>Task 2: Implement Auth-Aware UI and Logout</name>
  <files>
    - frontend/src/routes/+layout.svelte
    - frontend/src/lib/auth.ts
  </files>
  <action>
    1.  In `frontend/src/lib/auth.ts`, create a `logout` function. This function should:
        a. Clear the `jwt_token` store by setting it to `null`.
        b. Remove the token from `localStorage`.
        c. Redirect the user to the `/login` page.
    2.  In the main `frontend/src/routes/+layout.svelte`, subscribe to the `jwt_token` store.
    3.  Use an `{#if $jwt_token}` block to conditionally render the UI:
        - **If logged in:** Hide the "Login" and "Register" links. Show the user's email (this can be added to the JWT payload later) and a "Logout" button. The logout button should call the `logout` function.
        - **If logged out:** Show the "Login" and "Register" links.
    4.  In the main data-display page (`+page.svelte`), wrap the data-fetching and display logic in an `{#if $jwt_token}` block so that it only attempts to load and show commute data for authenticated users.
  </action>
  <verify>
    <checkpoint:human-verify>
      <what-built>UI now dynamically changes based on login state, and logout is functional.</what-built>
      <how-to-verify>
        1. Start with a clean session (clear localStorage). The header should show "Login" and "Register". The main page should show no commute data.
        2. Log in. The header should now show your user email and a "Logout" button. The main page should load and display your commute data.
        3. Click "Logout". You should be redirected to the login page, the token should be cleared from localStorage, and the header should revert to its logged-out state.
      </how-to-verify>
      <resume-signal>Type "approved" or describe issues</resume-signal>
    </checkpoint:human-verify>
  </verify>
  <done>
    The application UI is fully responsive to the user's authentication state, and a complete logout-to-login cycle is functional.
  </done>
</task>
