Output: A new `/analytics/commute-stats/daily` endpoint and corresponding tests.
</objective>

It will call the service function to get the data and return it.
4.  Create `tests/test_analytics_api.py` with a test case that seeds the database with `AssessmentHistory` records, calls the new endpoint, and asserts that the response contains the correctly aggregated data.

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-12-02 | Info. Disclosure | `/analytics/commute-stats/daily` | mitigate | Implement an authorization check in the endpoint to ensure the authenticated user's ID matches the `user_id` parameter in the query. This prevents Insecure Direct Object Reference (IDOR). |
| T-12-03 | Tampering | SQL queries in `service.py` | mitigate | Use of SQLAlchemy ORM inherently protects against SQL injection by parameterizing inputs. |
| T-12-04 | Denial of Service | `/analytics/commute-stats/daily` | accept | The risk of DoS from expensive queries on a large dataset is accepted for now. The research document notes this as a pitfall. If performance becomes an issue, future work will involve rate-limiting, query timeouts, or transitioning to DuckDB. |
| T-12-SC | Tampering | `pandas` install | mitigate | The `pandas` package was audited in `12-RESEARCH.md` and approved. The `slopcheck` was OK. |
</threat_model>
